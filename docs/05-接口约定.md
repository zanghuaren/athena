# 阶段 5：接口约定

> 状态：初稿 v0.1（2026-11-04）
> 同阶段：[05-技术方案](05-技术方案.md) · [05-数据库设计](05-数据库设计.md)
> 字段级的定义以后端自动生成的 OpenAPI 为准（开发时访问 `/api/docs`）。本文规定通用规则，并列出接口清单

## 1. 通用规则

### 1.1 基本

- 前缀 `/api/v1`；请求和响应都是 JSON（上传文件除外），UTF-8
- 字段名用蛇形（`next_review_on`），和数据库一致；前端用生成的类型，不做转换
- ID 是整数
- 时间用 ISO 8601，带时区：`2026-11-04T08:30:00Z`；只有日期的字段用 `2026-11-04`（北京时间的自然日）
- 分数用数字，保留 1 位小数
- 资源路径用复数名词；动作类接口用 `POST /资源/{id}/动作`，如 `POST /homeworks/{id}/withdraw`

### 1.2 认证

- 登录后拿到 `token`，之后每个请求都带上 `Authorization: Bearer <token>`
- 除注册、登录、体验入口外，所有接口都要求登录
- token 无效或过期返回 401，客户端跳到登录页，登录后回到原页面（02 第 16 节）
- 学生调用教师接口（或反过来）返回 403

### 1.3 列表与分页

```http
GET /api/v1/mistakes?subject=math&status=pending&page=1&page_size=20
```

```json
{ "items": [ ... ], "total": 57, "page": 1, "page_size": 20 }
```

- `page_size` 默认 20，最大 100
- 排序参数统一叫 `sort`，取值在各接口里列出，如 `sort=recent` / `sort=wrong_count`

### 1.4 错误

HTTP 状态码表示错误类别，响应体给出具体错误码和可以直接显示的中文提示：

```json
{
  "error": {
    "code": "USERNAME_TAKEN",
    "message": "用户名已被使用",
    "fields": { "username": "用户名已被使用" }
  }
}
```

- `fields` 只在表单校验错误时出现，客户端把提示显示在对应输入框下方
- 客户端优先显示 `message`；需要特殊处理的错误（比如跳转、置灰）按 `code` 判断

| HTTP | code | 场景 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | 参数格式不对（带 `fields`） |
| 400 | 各业务码 | 业务规则不满足，见下表 |
| 401 | `UNAUTHORIZED` | 未登录或登录过期 |
| 401 | `LOGIN_FAILED` | 用户名或密码错误 |
| 403 | `FORBIDDEN` | 没有权限访问 |
| 404 | `NOT_FOUND` | 内容不存在或已被删除 |
| 409 | `CONFLICT` | 状态已经变化，比如老师已开始复核，学生不能再提交 |
| 413 | `FILE_TOO_LARGE` | 文件超过 10 MB |
| 423 | `ACCOUNT_LOCKED` | 连续输错 5 次，锁定中（`message` 里带剩余分钟数） |
| 429 | `EXPERIENCE_QUOTA_EXCEEDED` | 今日体验次数已用完 |
| 502 | `AI_UNAVAILABLE` | 模型服务出错，主备模型都失败 |
| 504 | `AI_TIMEOUT` | 模型超时 |

常用业务错误码（400）：

| code | 提示 | 需求 |
|---|---|---|
| `USERNAME_TAKEN` | 用户名已被使用 | ACC-01 |
| `FILE_TYPE_UNSUPPORTED` | 只支持 jpg、png、heic、webp 格式的图片 | SCAN-01、ASK-01 |
| `INVITE_CODE_INVALID` | 邀请码无效，请向老师确认 | CLS-02 |
| `ALREADY_IN_CLASS` | 你已经在这个班级中 | CLS-02 |
| `CLASS_FULL` / `CLASS_ARCHIVED` | 班级已满 / 班级已归档 | CLS-02 |
| `CLASS_LIMIT` | 最多创建 10 个班级 | CLS-01 |
| `DEADLINE_TOO_SOON` | 截止时间至少在 1 小时之后 | HW-01 |
| `HOMEWORK_HAS_SUBMISSIONS` | 已有学生提交，不能撤回 | HW-01 |
| `DEADLINE_PASSED` | 已截止 | HW-03 |
| `NOT_ENOUGH_DATA` | 数据不足 | ANA-04 |
| `CONVERSATION_TOO_LONG` | 这个会话太长了，开一个新会话吧 | ASK-04 |
| `NO_QUESTION_FOUND` | 没有识别到题目 | SCAN-02、SCAN-03 |
| `PHOTO_UNCLEAR` | 照片不清楚（`message` 里带拍摄建议） | SCAN-03 |
| `MULTIPLE_QUESTIONS` | 请只框选一道题 | SCAN-02 |

### 1.5 超时与重复提交

- 普通接口服务端控制在 15 秒内返回；需要更久的一律做成长任务或流式接口
- 不做幂等键：客户端点击提交后按钮立即置灰，服务端按状态拒绝重复操作（比如提交已经在批改中，就返回 409）

## 2. 三种特殊接口

### 2.1 流式接口（SSE）

用于答疑和教案生成。请求是 `POST`，响应是 `text/event-stream`。客户端用 `fetch` 读取流（`EventSource` 不支持 POST）。

```text
event: start
data: {"message_id": 812, "conversation_id": 95}

event: delta
data: {"text": "我们先看看"}

event: delta
data: {"text": "这道题考查的是……"}

event: done
data: {"message_id": 812, "status": "done"}
```

| 事件 | 说明 |
|---|---|
| `start` | 开始生成，给出这条消息的 ID |
| `delta` | 一段增量文字，客户端追加显示 |
| `replace` | 内容安全拦截：用 `data.text` 替换已经显示的全部内容，之后紧跟 `done`，状态为 `blocked` |
| `done` | 结束；`status` 为 `done` / `blocked` |
| `error` | 出错；`data` 结构同 1.4 的 `error`，已经生成的部分保留在服务端，状态记为 `interrupted` |

- **停止生成**：客户端直接断开连接，服务端保存已经生成的部分，状态记为 `interrupted`
- **继续生成 / 重新生成**：再发一次请求，`action` 分别为 `continue` / `regenerate`。两者都不新增学生消息：继续生成接着最后一条已中断的回答往下写，`start` 给出的还是这条消息的 ID，`delta` 只含新增部分；重新生成删掉最后一条回答，生成一条新的（被拦截的回答不能重新生成）
- 生成前的错误（参数错误、次数用完）照常返回 JSON 错误，不建立流

### 2.2 长任务

用于整页批改、作业批改、PPT 生成、学情报告。

1. 创建资源的接口立即返回资源和任务 ID：

   ```json
   { "scan": { "id": 31, "status": "processing" }, "job_id": 770 }
   ```

2. 客户端每 2 秒查询一次 `GET /jobs/{id}`：

   ```json
   {
     "id": 770,
     "status": "running",
     "stage": "grade_questions",
     "stage_label": "逐题批改",
     "progress": 60,
     "error": null
   }
   ```

3. `status` 变成 `succeeded` 后，客户端重新获取资源本身（如 `GET /scans/31`）；变成 `failed` 时，`error` 里带错误码和提示，结构同 1.4 的 `error`（`{code, message}`）；重试等待期间 `status` 回到 `queued`

离开页面后重新进入，只要资源的状态还在处理中，就继续用资源里的 `job_id` 轮询。

### 2.3 文件

- **上传**：`POST /files`，`multipart/form-data`，字段 `file`；服务端校验格式（jpg / png / heic / webp）和大小（≤ 10 MB），统一转成 JPEG 并压缩

  ```json
  { "id": 101, "url": "/api/v1/files/101?exp=1730710800&sig=3f9a…", "width": 1536, "height": 2048 }
  ```

- 格式按文件内容判断，不看扩展名；不支持的返回 400 `FILE_TYPE_UNSUPPORTED`。转码时按 EXIF 方向摆正，长边压到 2048px
- 其他接口只传文件 `id`，比如提问时带 `image_file_id`；只能用自己上传的文件，别人的 `id` 按不存在处理（404）
- 返回的资源里，文件统一用上面这个结构（`id`、`url`、`width`、`height`），比如消息的 `image`
- 所有返回里的文件都带签名后的 `url`，至少 1 小时有效；过期后重新获取所属资源即可。签名按整点取过期时间，同一小时内多次获取得到同一个地址，浏览器可以缓存图片
- `url` 是相对地址，Android App 里要拼上服务器地址
- **导出**：导出接口直接返回文件流（`Content-Disposition: attachment`），比如 `GET /lesson-plans/{id}/export?format=docx`

## 3. 公共数据结构

字段定义见 [05-数据库设计](05-数据库设计.md) 第 10 节，这里只说接口层的差别：

- **题目 `Question`**：学生作答时（练习进行中、作业未发布）返回的题目**不带** `answer`、`analysis`、`scoring_points`；判分完成或按作业的可见设置允许后才带上
- **作答结果 `AttemptResult`**：`result`、`score`、`max_score`、`grading_status`、`grading_detail`、`error_reason`
- **知识点掌握度 `Mastery`**：`{ knowledge_point_id, mastery, level, attempt_count }`，`level` 为 `insufficient` / `weak` / `fair` / `good`

## 5. 权限规则

所有接口在服务端校验归属，不依赖前端隐藏（18.4）。按 02 第 17 节：

| 数据 | 谁能访问 |
|---|---|
| 会话、练习、拍照批改、复习、错题、学情画像 | 只有学生本人 |
| 作业的提交、成绩、评语 | 学生本人；这份作业的布置教师 |
| 班级名单 | 班级教师；学生只能看到班级名称、老师和自己 |
| 学生学情（ANA） | 班级教师，且只统计这个班的作业数据 |
| 试卷、教案、PPT、报告、教师录入的题目 | 只有创建者 |
| 任务进度 | 只有发起人 |

访问不属于自己的数据，返回 **404**，不返回 403：不让对方知道这条数据是否存在。

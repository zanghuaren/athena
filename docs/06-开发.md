> 下游：07-联调与测试

## 1. 阶段目标

做出[01 第 4 节](01-明确目标.md)完成标准里的“可以运行的功能”：

- 02 里所有**必做**功能都实现，接真实模型和真实识别，不留 mock
- 两条演示主线能完整跑通：
  - **学生线**：拍照批改 → 错题入本 → 讲解 → 变式练习 → 复习 → 学情变化
  - **师生线**：老师组卷并布置 → 学生提交 → AI 批改 → 老师复核发布 → 学生看结果 → 老师看学情报告
- Web 和 Android 用同一套代码，Android 能打包安装
- 体验模式可用，评委不用注册就能上手

加分项、正式部署和评测报告不算在本阶段的完成条件里，见第 4 节。

## 2. 开发方式

- 按[技术方案第 11 节](05-技术方案.md)的顺序推进，每一步拆成几**层**，每层可以独立验证，做完就单独提交一次，方便回退
- 每层的完成标准：后端测试通过（连真实 PostgreSQL），前端类型检查和 lint 通过；涉及页面的，在浏览器里按手机和电脑两种宽度实际走一遍
- 代码和文档不一致时，先改文档

## 5. 接下来需要准备的

### 5.1 需要你提供

| 内容 | 用途 | 什么时候需要 |
|---|---|---|
| **DeepSeek API Key** | 所有 AI 功能 | 开始做答疑时（第 4 步），越早越好 |
| **约 30 张真实作业照片**：数学、物理、英语都有，最好有学生手写作答，包括拍得不太好的 | 技术验证：看题目识别和手写识别能不能达标（印刷体 ≥ 95%，手写 ≥ 85%）；不达标要在识别阶段加专门的 OCR，会影响后面拍照批改的做法 | 越早越好 |
| **确认登录页**只留一个“登录”按钮 | 见 3.1 | 现在 |
| **正式域名** | 打一个能连服务器的 APK 到真机测试；正式部署 | 第 7 步之前；想早点在真机上试可以提前给 |

### 5.2 需要一起定的

| 内容 | 说明 | 什么时候需要 |
|---|---|---|
| **知识点目录** | 我按人教版初中数学、物理和英语语法维度先整理一版，你来审 | 第 3 步 |
| **预置题库从哪来** | 团队手上已有的题，还是先由模型生成再人工审核；每个知识点至少要有几道题，组卷和练习才够用 | 第 3 步 |
| **评测集** | 每科 ≥ 100 道题，带标准答案；拍照批改的评测还需要对应的作答照片和老师给的分数 | 第 7 步，可以提前慢慢攒 |
| **体验模式的模板数据** | 1 个班、30 名虚拟学生、3 次作业的批改数据。内容由我用模型生成，你来看是否像真的 | 第 7 步 |

### 5.3 下一步做什么

第 3 步，知识点和预置题库：

1. 建表：`chapters`、`knowledge_points`、`questions`、`question_knowledge_points`
2. 整理知识点种子数据，放在 `server/seed/`，能重复导入
3. 题目的内容和答案结构（数据库设计 10.1）落成 Pydantic 模型，按题型校验
4. 题目渲染：Markdown + LaTeX 公式（KP-03），前端出一个通用的题目组件
5. 接口：`GET /knowledge-tree`、`GET /knowledge-points/{id}`、`GET /questions/{id}`

然后进入第 4 步学生线，从答疑开始。答疑需要 API Key。

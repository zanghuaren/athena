- 按[技术方案第 11 节](05-技术方案.md)的顺序推进，每一步拆成几**层**，每层可以独立验证，做完就单独提交一次，方便回退

- 章节标题不带“第几章”，编号按年级内顺序（如 `M8-01` 三角形）。人教版 2024 年起逐年换新教材，新旧版章节编号不同，这样两版都对得上；各章所在年级暂按旧版

实测：

- **答疑首字**：`deepseek-flash` 默认开思考，首字约 2.4 秒；关掉思考后直接调用约 1.5 秒，经过我们的接口约 0.6 秒，满足 ≤ 3 秒
- 引导式讲解能按“点出考点 → 一步一问”进行；负面情绪会先关心、建议找老师家长并给出 12355；闲聊会礼貌拉回学习
- 模型默认用 `\(...\)` 写公式，提示词里要求 `$...$` 后输出正常

- **输入框的发送键在生成时变成“停止生成”**。原型没画这个按钮，ASK-01 要求有
- **AI 助教顶栏加了“历史记录”**。原型的 T-21 没有历史入口，但 ASK-04 的会话管理教师也需要

### 3.4 已完成：文件模块、答疑看图（5.3 的 A）

| 层 | 内容 |
|---|---|
| 文件模块 | `files` 表（迁移 0004）；`POST /files` 上传：按内容判断格式（jpg / png / heic / webp，其余返回 `FILE_TYPE_UNSUPPORTED`），> 10 MB 返回 413，按 EXIF 摆正、长边压到 2048、透明背景填白，统一存成 JPEG；`GET /files/{id}?exp=&sig=` 凭 HMAC 签名访问，不需要登录。文件放在 `FILES_DIR`（开发环境是 `files-data` 卷），签名密钥 `FILE_SECRET` |
| 答疑看图 | `messages.image_file_id`（迁移 0005），`MessageIn.image_file_id` 只能用自己的文件；消息返回 `image`（带签名地址）；上下文里有图就用 `MODEL_VISION`，图片以 data URL 交给模型；有图时提示词加 `ask/image`（看不清就说“没有看清题目”、多道题先问是哪道）；第一个问题带图时，标题也看图生成。后端测试共 72 个 |
| 公式渲染 | 前端 Markdown 也认 `\(...\)`、`\[...\]`（数据库设计 10.1） |

实测：

- 真实作业照片 3.7 MB → 1536×2048 JPEG 约 550 KB，上传加转码 0.4 秒
- 看图讲题：照片里的题目能正确读出并按引导式讲解；首字和纯文字差不多，整段回答约 5 秒
- 看图时模型常不听提示词，用 `\(...\)` 写公式（加强提示词后 8 次里仍有 3 次），所以改成前端两种写法都认
- 测试“空白图片回答没有看清”在十几次运行里失败过 1 次，没能复现，先保留观察

### 3.5 已完成：拍照识题 SCAN-02（5.3 的 B）

| 层 | 内容 |
|---|---|
| 识题接口 | `POST /recognize`（只限学生）：`MODEL_VISION` 按 `prompts/scan/recognize.md` 输出 JSON（`status` / `subject` / `text`），Pydantic 校验，不合格重新生成，最多重试 2 次；没有题目返回 `NO_QUESTION_FOUND`，多道题返回 `MULTIPLE_QUESTIONS`。只转写题目，不转写学生写的答案和批改痕迹。`app/ai/client.py` 加了通用的 `complete_json`，整页批改、出题都可以用。后端测试共 77 个 |
| 拍照页面 | S-03 拍照：拍照答疑 / 作业批改切换，相册和拍照按钮；S-04：Cropper.js 框选（可缩放）→ 识别 → 确认题目（文字可改、框选的图、学科默认取识别结果）→ 开始讲解；识别为空给“重新拍照”“手动输入题目”，多道题提示后可以直接调整框重新识别。确认后回到原来的会话发出（对话为空时新建），学科按确认时选的改 |
| 对话显示图片 | 学生消息上方显示附的图；学生消息也按 Markdown 渲染，识别出的表格、公式能正常显示 |

实测：

- 真实作业照片框选一道题（物理，含表格和手写作答）：约 2.5 秒，满足 ≤ 8 秒；题干和表格数据正确，手写的答案没有混进来
- 框里有两道题时，模型多数判为“多道题”，但另一道题的题号被裁掉时，偶尔只转写其中一道
- 提示词里要求了表格的分隔行，模型仍然 3 次里漏 1 次，改成代码补上
- 单独一行的 `____` 会被 Markdown 当成分隔线，前端已关掉分隔线语法

和原型、技术方案不一样的地方（2026-11-04 **已确认**）：

- **S-03 没有实时取景和“闪光灯”**：拍照和相册都调起系统自带的相机 / 相册（技术方案 3.1），闪光灯在系统相机里调；页面上的取景区只是提示“对准一道题”
- S-04 框选时多了一行操作提示；多道题时不单独换页，提示“请只框选一道题”后直接在原图上调整框，按钮变成“重新识别”
- **拍照先不用 `@capacitor/camera`**，用 `<input type="file">` 调起系统相机和相册，Web 和 App 同一套代码；真机上不好用再换
- **学生消息也按 Markdown 渲染**，识别出的表格、公式才能正常显示；代价是学生自己输入的 `*` 等符号可能被当成格式
- 框里有两道题、但其中一道的题号被裁掉时，模型偶尔只转写其中一道，不提示“请只框选一道题”，先接受

暂时没做的：

- **作业批改模式**：S-03 能切到“作业批改”，提示还在开发中，等 C（SCAN-03）
- 在 Android 真机上还没试过拍照（APK 还没装到真机，见 3.1）
- HEIC 照片在不支持的浏览器里显示不出来，提示换 jpg / png

**接手须知**

- 加后端依赖：容器里访问 PyPI 要走宿主机代理，用 `docker run --rm --network host -e HTTPS_PROXY=... -v <server目录>:/app athena-dev-api uv add <包>`，然后 `docker compose -f deploy/compose.dev.yml up -d --build api` 重建容器，否则热重载会因为缺包报错
- 调用真实模型的后端测试在没有 `DEEPSEEK_API_KEY` 时自动跳过；Key 在 `deploy/.env`
- 接口类型由 `npm run gen:api` 生成，有默认值的请求字段在类型里是必填（如发动作消息要传 `content: ''`）
- 提示词统一带 `prompts/safety.md` 和 `prompts/format.md`；模型默认用 `\(...\)` 写公式，必须在提示词里要求 `$...$`
- 需要思考模式的调用用 `Model.REASONING`，其余都关思考（首字和识别耗时）

### 3.6 已完成：识别快速试跑（第 1 步）

2026-11-04 用户决定：不做人工复核冻结，先快速试跑看方向；这次的数字**不作为正式准确率**，正式结论放到第 7 步的评测集。

做法：30 张照片（`eval/homework-ocr/`），我先逐张写了参考转写（印刷和手写分开，没有人工复核）；`run.py` 用和线上相同的 `MODEL_VISION`（关思考）和图片转码整页识别，`score.py` 按字符算准确率（先配对相同片段再算编辑距离，题目顺序不影响结果）。远拍双页 3 张的印刷字太糊，不评印刷体；physics-10 手写也大多看不清，不评。

| | 印刷体 | 手写 |
|---|---|---|
| 全部 | 96.2%（11218 字） | 82.1%（3938 字） |
| 数学 / 物理 / 英语 | 91.7% / 98.9% / 97.0% | 86.4% / 75.8% / 88.6% |
| 常规 / 困难 | 95.9% / 96.6% | 82.3% / 82.0% |

每页 2～9 秒。逐张看了低分的页，分两种：

- **评分口径造成的，模型没认错**：模型把参考转写没收的内容也转写了（页眉、附加题、作答区外抄写的单词），或把手抄的题干归成了印刷体。去掉这些，印刷体基本都在 95% 以上，清楚照片的手写大多在 85%～100%
- **真问题**，都和整页批改直接相关：
  1. **老师的红笔订正被当成学生的答案**（physics-07），提示词里写了也没管用
  2. **划掉的字也转写了**（math-08）
  3. **模糊的远拍照片上会编答案**（physics-05）：看不清时不说看不清，而是自己解一遍，把结果当成学生写的。这张是 1200×900 的双页照片，比手机正常拍一页的分辨率低很多

结论：**不加专门 OCR**。字本身认得准，问题出在分不清谁写的、哪些划掉了，以及看不清时乱猜，换专门的 OCR 也解决不了。整页批改（C）按下面的做法防护：

- 上传后先检查清晰度和分辨率，不够就按 SCAN-03 提示“照片不清楚”和拍摄建议，不往下批
- 识别作答时，每道题裁出原图里的区域单独识别，并要求给出“看不清”的选项；看不清或置信度低的题标为“？”，不判对错（SCAN-03 已有）
- 提示词里明确红笔、划改的处理；学生可以修改识别结果再重批（SCAN-03 已有）
- 做完用这 30 张再跑一次，重点看这三类问题有没有改善

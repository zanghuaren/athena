# 阶段 1：明确目标

> 状态：定稿 v1.1（2026-11-04，已确认全部待定项）
> 后续文档：[02-功能需求](02-功能需求.md) · [03-流程与原型](03-流程与原型.md)

## 1. 项目说明

### 1.1 基本信息

| 项 | 内容 |
|---|---|
| 产品名 | 雅典娜（暂定） |
| 性质 | 第二十届“挑战杯”全国大学生课外学术科技作品竞赛（大挑）参赛作品，非商业项目 |
| 平台 | Android App + Web |
| 学段 | 初中（七、八、九年级） |
| 学科 | 语文、数学、物理、英语（语文 2026-11-05 加入） |
| 教材 | 人教版 |
| 截止 | 2027 年，时间充裕 |
| 前身 | `reference/eduagent`（EduAgent），只作参考，不沿用代码 |

### 1.2 一句话定位

**连接学生和老师的 AI 学习助手**：学生用它答疑、批改、练习、复习；老师用它备课、布置和批改作业、看学情。两端的数据在“班级”里打通。

### 1.3 背景与要解决的问题

| 对象 | 痛点 | 雅典娜的解法 |
|---|---|---|
| 学生 | 遇到不会的题没人随时讲；直接搜答案抄了也不会 | 拍照或文字提问，AI 用**引导式讲解**分步提示，帮学生自己想出来 |
| 学生 | 做完作业不知道哪里错了，要等老师批 | 拍一张作业照片，AI **逐题批改**，并给出错因 |
| 学生 | 错题记在本子上，从来不复习 | 错题自动入本，按遗忘曲线安排**到期复习**，还能做同类变式题 |
| 学生 | 不知道自己哪里薄弱 | 每一次作答都落到知识点上，形成**知识点学情画像** |
| 老师 | 批改作业耗时 | 学生提交后 AI 先批，老师只做复核 |
| 老师 | 不清楚全班掌握情况，凭经验讲 | 作业数据自动汇总成**班级知识点热力图**和学情报告 |
| 老师 | 备课、出卷重复劳动多 | 按课题**一键生成**教案、PPT、试卷，可编辑、可导出 |

### 1.4 作品亮点（答辩主打）

1. **拍照整页批改**：一张作业照片 → 逐题判断对错 → 错题自动入本，并给出错因分析
2. **引导式讲解**：默认不直接给答案，而是分步提示，引导学生自己完成
3. **师生闭环**：布置作业 → 学生提交 → AI 批改、老师复核 → 学情自动汇总，老师不用手动录数据
4. **知识点学情画像**：学生看到自己的薄弱点，老师看到班级的知识点热力图
5. **一键备课**：教案、PPT、试卷生成，可编辑、可导出

## 2. 用户角色

| 角色 | 说明 | 主要终端 |
|---|---|---|
| 学生 | 初中生。可以单独使用，也可以加入班级接收作业 | Android 为主，Web 也可用 |
| 教师 | 初中语文 / 数学 / 物理 / 英语老师。注册时选教师身份即可使用，不做资格审核 | Web 为主，Android 做轻量查看和复核 |
| 体验用户 | 评委或访客。登录页一键进入体验，系统自动生成一组预置演示数据的账号，可以在同班的老师和学生视角之间切换 | 两端都可用 |

## 3. 第一版范围

功能分两档，详细需求见 [02-功能需求](02-功能需求.md)：

- **必做**：比赛演示的主流程，必须稳定可用
- **加分**：时间允许再做，用来增强演示效果

| 端 | 必做 | 加分 |
|---|---|---|
| 学生 | AI 答疑（引导式 / 直接讲解）、拍照识题、整页批改、错题本、变式题、AI 练习、到期复习、今日任务、学情画像、加入班级、提交作业、查看批改结果 | 语音提问、记忆卡片、错题集导出、作文批改、英语口语对练 |
| 教师 | 班级管理、AI 助教、教案生成、PPT 生成、AI 组卷、布置作业、AI 批改 + 人工复核、班级 / 学生学情分析、AI 学情报告 | 个人题库、重置学生密码 |
| 公共 | 账号密码注册登录、体验模式、个人资料与偏好、浅色 / 深色主题 | App 内消息提醒 |

**不做**：订阅支付、额度计费、自带 API Key、教师资格认证、管理后台、短信验证码、游客模式、多设备管理、注销和数据导出、系统推送、微信登录、内容审核和举报系统、学习计划、资料库和 RAG、家长端、学校端、官网。家长端和学校端写进答辩材料的“未来规划”。

## 4. 完成标准

1. Android 真机可以安装运行；Web 端在最新版 Chrome / Edge 上可用
2. 必做功能全部接真实模型和真实识别，不留 mock
3. 部署到云服务器，评委通过体验入口无需注册即可上手
4. 两条演示主线能稳定跑完：
   - 学生线：拍照批改 → 错题入本 → 讲解 → 变式练习 → 复习 → 学情变化
   - 师生线：老师组卷并布置 → 学生提交 → AI 批改 → 老师复核发布 → 学生看结果 → 老师看学情报告
5. 断网、模型超时、识别失败、空数据时都有明确提示；关键演示环节准备好兜底数据
6. 有 AI 效果评测数据：每个学科建立评测题集，统计讲解正确率和批改准确率（指标见 02 的非功能需求）
7. 有真实试用记录：至少一个初中班级试用，收集使用数据和反馈，作为作品实际应用的证明
8. 答辩材料齐全：作品说明书、演示脚本、演示视频、技术架构图、评测报告、试用报告

## 5. 约束与假设

- 人力、时间、预算充足
- 用户是未成年人：只收集必要信息（昵称、年级、班级内姓名），不收集手机号和身份证；AI 输出要有面向未成年人的安全约束
- 知识点体系按**人教版**教材组织，依据《义务教育课程标准（2022 年版）》
- 物理从八年级开始开设，七年级学生默认不显示物理
- 技术方案（框架、模型、服务怎么拆）在阶段 5 决定

## 6. 旧项目问题与新设计的处理

| # | 旧项目的问题 | 新设计 |
|---|---|---|
| 1 | 没有班级和作业，老师和学生之间没有连接；学情只能靠老师上传 CSV | 班级 + 作业作为两端的连接点，学情直接来自作答数据 |
| 2 | 聊天工具栏 16 个按钮平铺，输入方式、学科技能、页面跳转、教师功能混在一起 | 附件只是输入方式，意图由 AI 判断，学科能力自动生效，教师功能进教师工作台 |
| 3 | 拍照答疑、作业批改、文档解析三个入口，本质都是“传一张图” | 合并为一个拍照入口，识别后按内容分流 |
| 4 | 出题有四套（卡片出题、知识点检测、错题变式、试卷生成） | 统一的题目模型 + 出题引擎 |
| 5 | 错题和卡片各用一套复习算法 | 统一的复习规则 |
| 6 | 历史记录做了四份 | 每个模块只保留自己的列表 |
| 7 | 学习计划和错题、复习都不相关 | 用“今日任务”自动汇总复习和作业 |
| 8 | AI 记忆和知识点掌握度是两套学情数据 | 统一成学情画像 |
| 9 | 范围过大、架构先行（7 个微服务、自建模型、大量编排机制），核心功能仍是 mock | 收窄到比赛需要的功能，先跑通真实闭环 |

## 7. 术语表

| 术语 | 含义 | 不要混用 |
|---|---|---|
| 答疑 | 学生和 AI 的对话 | — |
| 识题 | 拍一道题，识别后进入答疑讲解 | — |
| 批改 | 对一份作答（拍照或在线）逐题判断对错、给分 | — |
| 练习 | 学生自己发起的做题 | 不叫“作业” |
| 作业 | 老师布置给班级的一组题 | 不叫“任务” |
| 试卷 | 老师组的一套题，可以导出，也可以布置成作业 | — |
| 错题 | 做错的题，以及作答和错因 | — |
| 复习 | 到期的错题再做一遍 / 回顾一遍 | — |
| 今日任务 | 学生端“今日”Tab 汇总的当天待办：作业 + 复习 + 推荐练习 | — |
| 知识点 | 按学科、年级、章节组织的最小教学单元 | — |
| 掌握度 | 学生在某个知识点上的掌握程度 | — |
| 学情画像 | 学生在所有知识点上的掌握度及薄弱点 | — |
| 学情分析 | 老师视角下的班级 / 学生统计 | — |
| 体验模式 | 免注册的演示账号组 | 不叫“游客” |
